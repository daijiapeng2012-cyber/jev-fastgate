01 PURPOSE

把窄问题交给快判断，把复杂问题留给深度推理。

Agent 工作流里有很多问题并不需要完整推理：该走哪个分支、证据够不够、风险高不高、是否需要复核。FastGate 只处理这一层。

01

Route · 路由

决定走规则、FastGate、Codex 深度推理，还是人工复核。

02

Score · 评分

把风险、准备度、质量和证据充分性放入明确尺度。

03

Verify · 验证

对验收条件做独立检查，但不替代测试和代码 Review。

02 WORKFLOW

门负责判断，司机负责行动。

能写死的先写成规则；足够封闭的问题交给 FastGate；开放式推理、研究、代码和调试交给 Codex；最后由正式 Gate 放行。

04 BEST FIT

先从判断密度最高的地方开始。

FastGate 适合做清晰、可比较、可回退的判断，不适合替代开放式思考。

05 BOUNDARY

判断信号，不是安全边界。

FastGate 的结果需要被验证。它不能把低置信度变成事实，也不能跳过测试、Review 或人工批准。

不包含 API Key

公开页面只展示 TYPESAFE_API_KEY 变量名。

低置信度回退

超时、冲突、高风险动作都回到 Codex 或 Reviewer。

正式 Gate 仍在最后

部署、发布和高影响动作保持原有批准边界。
